# 港口运营总监子页 — 数据与接口设计说明

本文档记录 **港口运营总监**（`port_director`）角色下七个顶部导航对应的业务视图、主要展示内容，以及前端获取数据的方式（REST / WebSocket）。当前后端为 **演示用 Dummy数据**，实现位置见文末「代码引用」。

---

## 1. 导航与数据通道总表

| 导航 | 主要内容 | 数据方式 | 接口或消息 |
|------|----------|----------|------------|
| **首页**（港口业务全景） | 主屏为 **Cesium 3D 地图**；全景数据拆为多个**可拖动、可折叠**的浮动小部件叠在地图上（核心 KPI、到离港摘要、分时趋势、预警速览），不再使用固定左右侧栏 | **REST** 基线 + **WebSocket** 推送 KPI | `GET /api/director/overview`；`WS /ws` 消息类型 `director_overview_update`（约每 3s，与现有广播同周期）；布局与折叠状态可持久化在浏览器 `localStorage`（`jeddah-overview-widget:*`） |
| **货运** | 当日货运船舶到港/离港明细；货物装卸进度；堆场库存；货运车辆转运效率；重点货主、重点货类 | **REST**（页面支持手动刷新） | `GET /api/director/freight` |
| **客运** | 客轮到发计划；各航线客运量与客座；检票进度；候车厅占用；高峰时段与热门航线 | **REST**（页面支持手动刷新） | `GET /api/director/passenger` |
| **资源统筹** | 泊位利用率；设备使用效率；人员排班到岗；计划 vs 实际；闲置/紧张环节 | **REST**（页面支持手动刷新） | `GET /api/director/resources` |
| **异常响应** | 业务异常列表：类别、原因、影响范围、状态、责任岗位、处理进度、更新时间 | **REST**（页面支持手动刷新） | `GET /api/director/exceptions` |
| **业务决策** | 决策项：依据、动作、下达对象、下达时间、执行状态与效果评分（演示） | **REST**（页面支持手动刷新） | `GET /api/director/decisions` |
| **业务总结** | 日终概览（货运/客运/资源/异常）；目标对比；管理洞察要点 | **REST**（页面支持手动刷新） | `GET /api/director/summary` |

## 2. 设计原则（为何 REST / WS 如此划分）

- **首页 KPI**：需要「进入系统即可感知变化」，与全局孪生推送节奏一致，采用 **WebSocket** 推送指标快照（带小幅随机波动以模拟实时性）；**REST** 提供完整基线（趋势、摘要、预警列表等静态结构）。
- **货运 / 客运 / 资源 / 异常 / 决策 / 总结**：以 **表格、卡片、报告** 为主，数据体量与变更频率相对可控，采用 **REST** 在进入页面或点击「刷新数据」时加载；后续若需单页实时刷新，可对该资源增加 WS 频道或短轮询。

## 3. WebSocket：`director_overview_update` 载荷（KPI 快照）

与 `ship_update`、`stats_update` 并列推送，载荷字段含义如下（演示数据，字段名以实际 JSON 为准）：

| 字段 | 说明 |
|------|------|
| `cargoThroughputTeu` | 当日货运吞吐量（TEU），演示中为波动值 |
| `passengerDispatch` | 当日客运发送量（人），演示中为波动值 |
| `shipPlanCompletionRate` | 船舶到离港计划完成率（0–1） |
| `criticalExceptionCount` | 核心业务异常件数（整数） |
| `updatedAt` | ISO 时间戳 |

完整全景 JSON结构（含 `hourlyTrend`、`shipPlanDigest` 等）以 `GET /api/director/overview` 响应为准。
